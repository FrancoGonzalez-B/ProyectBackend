1 · Problema y usuarios · 0:35

¿Qué problema abordamos?

  • Una tienda debe mantener coordinados catálogo, tallas, colores y existencias.
  • Los administradores necesitan registrar cambios y conocer el stock disponible.
  • Los clientes necesitan consultar productos y revisar sus compras.
  • Un inventario desactualizado puede causar ventas sin disponibilidad y pedidos difíciles de seguir.

1 · Alcance y aceptación · 0:50

Qué resuelve esta versión

  • Registrar e iniciar sesión; administrar clientes, categorías y productos.
  • Administrar variantes, consultar el catálogo y procesar pedidos.
  • El catálogo permite filtro, búsqueda, orden y paginación en una consulta.
  • Fuera de alcance: frontend, pasarela de pago real y despacho/logística.
  • Aceptación: CRUD, errores controlados, reglas de stock y cambios persistentes tras reiniciar.

Variante 1 → N Detalle

Las relaciones 1:N se guardan en MySQL mediante claves foráneas.

2 · Modelo del dominio · 0:30

Atributos que describen el negocio

Usuario/cliente: nombre, apellido, email, rol, teléfono y dirección.

Categoría: nombre, slug, descripción y estado activo.

Producto: nombre, SKU, descripción, precio, stock y categoría.

Variante: SKU, talla, color, precio, stock y producto.

Pedido: cliente, dirección de envío, estado, fecha y total.

Detalle: pedido, producto, variante, cantidad y precio unitario.

Cada entidad cuenta además con un identificador único.

2 · Reglas de negocio · 0:45

Inventario y pedidos coherentes

  • Stock: se controla por variante; el total del producto refleja la suma.
  • Precio: el servidor lee el precio vigente y calcula el total en centavos.
  • Transacción: pedido, detalles y descuento de inventario se confirman juntos.
  • Estados: el pedido avanza paso a paso; sólo uno pendiente puede cancelarse.
  • Cancelar repone las unidades una sola vez; una operación inválida no deja cambios parciales.

2 · Validaciones y respuestas · 0:40

Validar antes de persistir

  • Se comprueban longitudes, formato de correo, precio, cantidad e IDs.
  • Estados y tipos admitidos son conjuntos controlados.
  • Se verifica la existencia de categorías, clientes, productos y variantes.
  • Duplicados y conflictos de inventario reciben errores controlados.
  • Los errores usan JSON uniforme: código, mensaje y detalles; HTTP distingue 401, 403, 404, 409 y 422.

3 · MySQL, migraciones y seeders · 0:30

Preparar la base de datos

  • Node.js 22.12+, npm y MySQL/MariaDB (XAMPP sirve para desarrollo local).
  • npm ci; copiar .env.example a .env y configurar conexión/secreto.
  • Ejecutar npm run db:create, npm run db:migrate y npm run db:seed.
  • El seeder carga 2 categorías, 2 productos, 3 variantes, 2 clientes, 2 pedidos y sus detalles.
  • npm run db:verify comprueba integridad. No usar credenciales reales en Git.

5 · Decisiones y mejoras · 0:40

Decisiones y limitaciones

  • Separar variantes permite saber qué talla y color tienen existencias.
  • Sequelize y las migraciones versionadas permiten evolucionar el esquema con control.
  • Las transacciones protegen pedido, detalles e inventario frente a errores.
  • La versión no procesa pagos reales ni coordina despachos.
  • Mejoras futuras: pasarela de pago, seguimiento logístico y alertas de stock bajo.
